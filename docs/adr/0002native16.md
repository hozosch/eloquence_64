# Native 16 kHz mode

Version 20 replaces the external 11.025→22.05 kHz output upsampler with a
native 16 kHz Eloquence mode.

## Runtime switching

The original 8 kHz and 11.025 kHz voice data remains the baseline. Those two
rates are native modes of the already-loaded Eloquence engine and can therefore
be changed live through ECI parameter 5.

The 16 kHz mode additionally changes the synthesis module itself. The add-on
stores compact reversible `.p16` patches for every supported Eloquence voice.
The selected release mode has two internal variants so the optional native
presence contour can be enabled or disabled.
When 16 kHz is selected, the patch is applied to the corresponding `.SYN` file
**before the module is loaded**. The 32-bit helper normally stays alive while
its ECI runtime is unloaded and re-created; a full helper restart remains the
fallback. NVDA itself stays running. Switching back to 8 or 11 kHz restores the
original bytes before ECI is reloaded.

This ECI reload is necessary because an already-loaded `.SYN` module keeps its
code and tables in process memory; changing the file on disk cannot safely turn
that live instance into the patched native-16 engine. Restarting the isolated
runtime lets Eloquence load the correct module normally, avoids unsupported live
patching of proprietary in-memory code/data, and makes the operation reversible.
After reinitialization the add-on restores the language, voice variant/synthesis
model, and user voice parameters, then applies ECI parameter 5 for 16 kHz.

Two startup costs are reduced without changing the proprietary engine.  SYN
variant selection keeps each complete module in memory while checking its
compact patches, reducing the operation to one file read and at most one write
per language.  New 32-bit helper builds use PyInstaller's `onedir` layout, so a
host restart launches the already-extracted runtime instead of unpacking a
six-megabyte onefile executable every time.  The client retains support for the
older onefile helper as a fallback, including in locally assembled test add-ons
that have not rebuilt the 32-bit helper yet.

Current helper builds additionally support a warm engine reload. The controller
deletes the ECI handle, explicitly unloads `eci.dll`, changes the SYN files, and
creates a fresh ECI runtime over the existing process and named pipe. If an ECI
release keeps a voice module mapped or any step fails, the controller retries
with the established full-process restart. This removes Python/PyInstaller
startup from the normal sample-rate switching path without weakening recovery.
An already-correct `ECI.INI` is no longer opened for a redundant rewrite. The
WavePlayer-retention experiment did not measurably improve switching time and
was removed from the release path. The actual ECI handle/SYN reload remains
necessary.

The Presence contour is part of the native SYN output processor. Toggling it
while 16 kHz is active therefore performs the same warm ECI reload used for a
native-rate change. The add-on deliberately does not rewrite executable module
memory while a language is loaded; that would make the switch faster, but would
reintroduce a language-dependent crash surface.

A native 64-bit ECI build is not part of this design.  The available ECI DLL
and the executable code embedded in the SYN modules are 32-bit x86 binaries;
without their original source they cannot be safely recompiled for x64.  The
small isolated 32-bit host therefore remains the compatibility boundary.

## v20 tuning

The v20 native-16 tuning includes:

- the sixth cascade formant enabled;
- a small general consonant/noise gain increase (+1.5 dB);
- focused tuning of parallel stages 5 and 6 for sibilants;
- for all languages except Italian, an 80% native / 20% shaped blend for the
  stage-5/6 sibilance component;
- Italian retains the stronger shaped sibilance treatment that matched its
  native 16 kHz output best;
- no global voiced-source attenuation.

The patch files contain only the byte-level differences needed to activate and
tune the native 16 kHz path. The original proprietary `.SYN` data is not stored
in the repository.

## Development history

The experiments below led to the final target-routed mode. They remain documented
for reproducibility but are not exposed as sample-rate settings in release builds.

### Native-s comparison mode

An experimental second native-16 setting changes only the final sibilance blend
from 80% native / 20% shaped to 100% native / 0% shaped. The blend is performed
between two phase-related signals; frequency-response analysis shows that the
20% shaped component progressively cancels energy above roughly 5.5 kHz. The
comparison setting removes that cancellation at its source while deliberately
keeping the successful separate frication filter used by `f`, the sixth
cascade, the general consonant gain, and all other native-16 changes. The
established 16 kHz setting remains available for direct comparison.

`tools/make_native_s_patches.py` derives the `.p16n` files mechanically from the
established `.p16` files. It changes only the shaped-s blend factor and validates
the surrounding filter coefficient table before writing each patch.

### Full-band extension comparison mode

A further experimental setting combines the true native sibilance path with a
+10 dB high shelf applied to the complete summed 16 kHz signal. The transition
is centred at 4.8 kHz so that the newly available band above the original
11.025 kHz Nyquist limit is already close to the full boost and reaches +10 dB
from approximately 6 kHz onward. This affects every synthesis component in the
extension band, including frication, aspiration, and voiced energy, rather than
only the dedicated sibilance path. The filter state is preserved across audio
chunks and reset between Speech Generations.

Three additional comparison curves distribute the same final +10 dB boost over
two shelves so that the rise begins before the extension band:

| Setting | 3 kHz | 4 kHz | 5 kHz | 5.5 kHz | 6.5 kHz and above |
| --- | ---: | ---: | ---: | ---: | ---: |
| Gentle rise | +1.6 dB | +3.4 dB | +6.4 dB | +8.1 dB | about +10 dB |
| Medium rise | +2.6 dB | +4.6 dB | +7.5 dB | +8.8 dB | about +10 dB |
| Early rise | +3.9 dB | +5.9 dB | +8.4 dB | +9.3 dB | about +10 dB |

All three retain the true native sibilance patch and the established frication
treatment. They differ only in the full-output bandwidth balance.

### Measured voiced-energy reference

Two recordings of the same material, one native and one externally adjusted to
the preferred voiced-energy balance, were dynamically aligned at 10 ms
resolution. Their matched energy envelopes correlate at 0.95. Measurements over
272 matched voiced frames show that the target is closely represented by a
single broad +8 dB shelf centred at 3.43 kHz with a slope of 0.406. Its RMS error
against the measured half-kilohertz bands is approximately 0.19 dB.

The corresponding comparison mode retains the true native sibilance and the
established frication treatment. The reference recording was explicitly not a
target for consonant quality, so this curve establishes only the voiced-energy
balance; consonant noise requires a separate comparison against the original
11 kHz output.

### Sixth-cascade isolation

A further comparison mode uses the same measured voiced-energy curve, true
native sibilance, and established frication treatment, but restores the original
five-cascade count. Its `.p16b5` patch differs from the corresponding `.p16n`
patch by exactly one byte in the synthesis loop-bound instruction: five cascade
formants are processed instead of six. The separate PE section-count patch
remains at six so the injected `.xflt` section stays mapped and executable. This
isolates whether the sixth cascade causes the voiced high-frequency sizzle that
became audible after restoring the preferred upper-band energy.

### Focused frication comparison

After the B6 comparisons selected four times the native B6 bandwidth, that
setting became the fixed experimental baseline together with true native
sibilance and the measured +8 dB voiced-energy shelf. Intermediate shelf curves,
B6 multipliers, the five-cascade isolation, and the PCM voiced/unvoiced detector
are no longer exposed as selectable modes.

Two focused variants process Eloquence's internal frication buffer before its
direct and parallel-filter contributions are mixed into the voiced signal. The
first applies only the adaptive slew smoothing from the former 11.025→22.05 kHz
upsampler. The second also ports its 6.3 kHz SVF presence stage and 7.5 kHz notch.
Because native 16 kHz frication contains real upper-band noise that the
interpolated 11 kHz source did not, the full treatment uses a compensating 0.5
gain. Neither variant detects consonants from the completed PCM signal, and
neither changes the voiced cascade, its four-times B6 bandwidth, or the measured
balance shelf.

The selected release mode keeps the voiced cascade and the full frication
treatment ported from the former upsampler unchanged. Its additional processing
runs only after the engine has separated the signal paths. The direct contribution, which carries
much of `f`, `w`, and the `p`/`b` bursts, gets the spectral pivot and a further
2 dB attenuation. Parallel formant stages 1--4 get the pivot independently for
the resonant `ch` and `sch` components. Each stage has separate filter state.
Parallel stages 5--6 tail-jump directly to the original `s`/`t` mixer and never
enter the additional filter. A dedicated-stage guard additionally bypasses the
stage-1--4 and direct pivots whenever stage 5 or 6 carries sibilance. Routing
reads the engine's current target flags for those stages, rather than their
interpolated gains. Those gains intentionally decay across synthesis-frame
boundaries and could therefore capture a following filtered consonant even
with a short hold. The target flags change at the actual frame boundary and
need neither a hold nor a fade. Both added filter states are cleared during the
native bypass so a preceding `f` or `ch` cannot colour the protected interval.
Unvoiced `ch`/`sch` keeps the preferred filtering, and voiced `w`/`v` remains
on the direct filtered branch because it does not activate stages 5--6.

The added response is a spectral pivot rather than a gain-reducing notch. It
adds about +6 dB below 2 kHz, crosses 0 dB near 3.9 kHz, and then falls to
approximately -5.4 dB at 5 kHz, -8.9 dB at 6 kHz, and -10 dB throughout
7--8 kHz. Unlike the preceding experiment, selection no longer depends on
instantaneous voiced/unvoiced estimates and uses no crossfade on the shared
source. The engine's existing direct and parallel branches plus the exact
per-stage target flags are the separation mechanism, and the original
stage-5/6 `s`/`t` code remains byte-for-byte unchanged.

All injected calls are calculated from the established `.xflt` entry call, not
from the appended section's raw file offset. Several language modules map the
new PE section at an RVA that differs from its raw offset by one or two 4 KiB
pages; treating the raw offset as a runtime address makes those calls jump
outside the filter code.

### Selected release output contour

The release exposes only one 16 kHz setting. Its final output processor runs on
Eloquence's float buffer before PCM16 conversion and applies, in order:

- a +2 dB low shelf at 220 Hz;
- the measured v21-reference high shelf at 3.43 kHz, +8 dB, slope 0.406;
- when Presence contour is enabled, a +8 dB peak at 4 kHz with Q 1.5.

The earlier Q 1.25, Q 1.0, no-bass, and upper-mid comparison settings are no
longer packaged or exposed. The output processor also brings the general voiced
path to -1.5 dB. It uses the engine's hard active-voice and exact s/t/z target
flags only to choose the gain target; a persistent one-pole envelope with a
0.04 per-sample coefficient performs the transition. At 16 kHz this is roughly
a 1.5 ms time constant and about 4.6 ms to 95%, avoiding the click caused by a
frame-wide gain step while keeping the protected sibilant path at unity.
